# Защита курсовой работы ПМ4

Тема № 20 — «Разработка REST API для системы учёта посещаемости студентов». Расчётная продолжительность выступления вместе с демонстрацией — 6 минут 35 секунд.

## Подготовка

1. Заполнить красные поля на титульном листе записки и первом слайде. Дату допуска и оценку вносить после их получения.
2. Открыть [пояснительную записку](Пояснительная%20записка%20ПМ4.docx), [презентацию](Презентация%20защиты%20ПМ4.pptx) и [ветку курсовой на GitHub](https://github.com/toxonpf/learning/tree/coursework/pm4-attendance).
3. Запустить PostgreSQL и журнал по [README](../README.md#запуск). Для демонстрации на новом компьютере подготовить пустую базу и использовать `npm.cmd run db:seed -- --demo` при первом заполнении. После этого запустить `npm.cmd start`.
4. Открыть [приложение](http://127.0.0.1:3000). В одной вкладке выбрать демонстрационную группу ПО-24/1. В отдельном окне браузера открыть приложение под студентом. Учётные данные администратора и пароли демонстрационных пользователей берутся из локального `.env`.
5. В отдельном PowerShell перейти в папку проекта. Подготовить команду `npm.cmd run demo:defense`, чтобы выполнить её на слайде 10. Сценарий рассчитан на демонстрационную базу.

## Ожидаемый вывод демонстрации

```powershell
npm.cmd run demo:defense
```

| Проверка | Ожидаемый HTTP |
| --- | --- |
| Чтение групп без JWT | 401 |
| Вход администратора, студента и преподавателя | 200 |
| Публичная регистрация и роль `user` | 201 |
| Создание статуса с токеном студента | 403 |
| Та же операция с токеном администратора | 201 |
| Создание занятия и отметки под преподавателем | 201 |
| Чтение списка и своей отметки со связанными полями | 200 |
| Изменение примечания и удаление отметки | 200 |
| Чтение удалённой отметки | 404 |

Сценарий удаляет свою отметку и занятие, затем архивирует созданный статус. В демонстрационной базе остаются учебная запись о регистрации и архивный статус. Обычные группы и выставленные ранее отметки сохраняются.

## Вопросы комиссии

**Зачем шесть сущностей?** Группы, пользователи и занятия описывают участников процесса. Отдельный период участия позволяет восстановить состав на дату занятия. Отдельный справочник даёт настраиваемые статусы. Отметка связывает эти записи.

**Откуда известно, что студент относится к этому занятию?** Сервис подбирает период на дату занятия. Два внешних ключа PostgreSQL связывают отметку с занятием и периодом одной группы.

**Чем пустая ячейка отличается от отсутствия?** Пустая ячейка означает, что запись ещё не выставлена. Отсутствие — сохранённая отметка со своим статусом.

**Что происходит при одновременной отметке?** Транзакция контролирует чтение и запись. Уникальный ключ исключает дубли. Массовое заполнение добавляет только отсутствующие строки.

**Почему студент не может записать посещаемость другого?** Маршруты записи требуют роль преподавателя или администратора. Чтение для студента фильтруется по идентификатору из проверенного токена и текущей записи аккаунта.

**Чем подтверждён запуск?** Миграция и интеграционные тесты выполнены на PostgreSQL 17. Для браузерной демонстрации используются вымышленные пользователи и заранее подготовленная база.
